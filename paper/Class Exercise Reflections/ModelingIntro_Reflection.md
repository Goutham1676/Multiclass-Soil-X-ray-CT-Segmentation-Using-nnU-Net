## Reflection

The class exercises were useful because they showed me how to take code that works in a notebook and make it more organized, reusable, and reproducible. I found it especially helpful to break the code into functions and move the reusable functions into a separate Python module BaTri.py, which could then be imported and tested from a notebook. Using autoreload, Git, and Ruff also helped me understand how to keep code updated, track changes, and maintain consistent formatting. The Git exercises were particularly useful because they showed me how to stage only the files I want, commit changes with meaningful messages, push them to GitHub, and verify the status of the repository. Ruff was also useful for identifying formatting and code-quality issues automatically instead of checking everything manually.

These ideas will be useful for my individual project, where I plan to use nnU-Net for segmenting soil µCT images into classes such as soil matrix, stones, organic matter, roots, biopores, and other pores. Instead of keeping all preprocessing, training, evaluation, and visualization steps in one large notebook, I can organize the workflow into reusable Python functions and modules. This would make it easier to separate different parts of the analysis, test them independently, and reuse the same code across different datasets or model runs. Git will allow me to track changes to the segmentation workflow and recover earlier versions if changes introduce problems, while Ruff can help keep the Python code consistent and readable. Overall, these practices will help make my project more reproducible and easier for another researcher or collaborator to understand and run later.
